Buzz Setup: Unit 3 Lesson 4 Collision Lab

What this activity is

The assessment template shows the five collision trials one after another down the page, and each trial has its own embedded simulator — a trimmed canvas sim (Run Collision / Reset, with velocities shown as labeled arrows on the balls) locked to that trial's fixed conditions, driven by one shared script at the bottom of the template. Buzz cannot open linked/hosted files from a template, so the simulation code lives inside the template itself.

Below each simulator is that trial's data chart, with columns in chronological order: Mass, Initial Velocity, Total Momentum BEFORE, Final Velocity, Total Momentum AFTER. The two momentum columns each contain a real Buzz question placeholder (<a:question></a:question>) in the same row as the other values. Every velocity in the chart — the given initial velocities and what students record — is a magnitude with a direction arrow (→/←), never a +/− sign, so students must apply the sign convention themselves for both momentum calculations. The yellow Final Velocity cells are interactive: a number box for the speed plus a two-choice arrow picker (→ or ←). When a student enters the correct speed and picks the correct arrow, the cell locks into a plain value-and-arrow display styled like the given cells (e.g. 1.00 ←) — confirming their reading before they calculate momentum. Wrong entries get no feedback; the cell just stays editable. These are on-page self-check inputs only — not graded or saved (a page reload clears them); the graded answers are the momentum Buzz questions. Note the correct finals appear in the page markup as data attributes, but they are also visible on the simulator balls, so nothing gradable is exposed. That makes ten numeric Buzz questions, two per trial, followed by four written-answer (essay) questions at the bottom — fourteen questions, 18 points total.

Every trial's initial conditions and elasticity are fixed (100% for Trials 1–3, 0% for Trial 4, 50% for Trial 5/Explore; shown at the bottom center of each canvas), so all students collect identical data and every question grades cleanly.

The template contains no solving help by design: no directions card, formulas, sign hints, or conclusions — each trial shows only its setup facts, the simulator, and the chart, and every numeric question simply asks students to record the total momentum before/after. Students must bring p = mv and the sign convention (right = +, left = −) themselves; the standalone practice simulator (collison-lab.html, linked from the Unit 3 menu) keeps the Guide and Hint overlays for teaching before the assessment. A wrong sign on an AFTER question usually means the student skipped the arrow-to-sign conversion.

Step 1: Nothing to host

The template is fully self-contained — the five trial simulators are embedded in it, so there is no separate simulator upload and no link to replace. (collison-lab.html remains in this folder as the standalone practice version linked from the Unit 3 menu; it is not needed for Buzz.)

If Buzz strips the template's script (the simulators do not draw in preview): host collison-lab.html on a web server and add a link to it in the template's directions card instead.

Step 2: Create the fourteen Buzz questions

  2. Open buzz-assessment-questions.txt and paste the full contents into the Buzz Assessment text editor / Edit all questions screen. The file is pure Buzz text-editor syntax with no header notes, so it can be pasted whole.
  3. It creates the fourteen questions in slot order: ten Fill in the Blank (Number) questions graded by explicit ranges (Trial 1 before, Trial 1 after, … Trial 5 after), then four essay questions (11: momentum before vs after; 12: how total momentum can be zero while the balls move; 13: whether total velocity is conserved; 14: why real colliding objects come to rest). The essays' a. lines are grader guides, not auto-graded keys.

Step 3: Upload the template

  1. Upload buzz-assessment-template-for-buzz.html as the assessment template.
  2. The template has fourteen <a:question></a:question> slots; Buzz fills them with your fourteen questions in order, so the question order must match the slot order exactly.
  3. Open buzz-assessment-template-preview.html locally first to see where each question lands.

CRITICAL: Buzz assessments default to RANDOMIZED question order, and the template fills its placeholders in display order — randomization puts questions in the wrong chart cells (this is what scrambles the trials). In the assessment settings, turn OFF randomize/shuffle question order so questions display in their created order. Also do NOT set one question per page: each trial's two momentum questions must render together inside that trial's chart.

Step 4: Preview as a student

  1. Confirm each of the five trial simulators draws its track and balls, and that pressing Run Collision animates the collision (this verifies Buzz did not strip the template script).
  2. Confirm each trial chart shows its two Buzz answer boxes inside the BEFORE and AFTER columns — in order, top to bottom: Trial 1 gets questions 1–2, Trial 2 gets 3–4, Trial 3 gets 5–6, Trial 4 gets 7–8, Trial 5 gets 9–10. If they land in the wrong charts, question randomization is still on.
  3. Run Trial 1 and confirm the velocity labels on the balls show v₁ = 1.00 m/s (arrow pointing left) and v₂ = 2.00 m/s (arrow pointing right) after the collision — magnitudes with arrows, no signs — and the elasticity reads 100% at the bottom of the canvas.
  4. Enter the answer-key values above and confirm all ten numeric questions grade correct.
  5. Scroll to the bottom and confirm the four written-answer questions (11–14) each show an essay box inside their analysis card.
