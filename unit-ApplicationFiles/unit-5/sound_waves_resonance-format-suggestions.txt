Deviations from the conversion guide:
- No "Copy values for Buzz" button. The integrity guard's capture-phase paste handler also
  fires on the Buzz question controls, so students could copy but never paste. The values
  stay readable in the data table and the evidence PNG, and students type the short numbers.
  Unit 6 Lesson 2 set this precedent.
- Download CSV was kept. It is a file download, not a clipboard action.
- The model note about the open-end correction was kept. It states a limitation of the
  simulation; it does not help with any graded question.

Grading design:
- Student-dependent validation. getCalculationResult() checks each row's L(m), wavelength,
  and speed against THAT student's recorded length; getFinalResult() checks the average
  against that student's own 12 speeds. Those row calculations are therefore NOT re-graded
  in Buzz as fixed numerics - that would grade one student's arithmetic against another
  student's measurement.
- The record threshold accepts a peak only within |delta| <= gamma/3, where
  gamma = clamp(L_target/80, 0.22, 1.25), on a 0.1 cm grid. Short air columns are
  effectively single-valued; the 256 Hz long columns admit up to nine distinct lengths.
  Q2-Q4 therefore auto-grade only the 1st-harmonic lengths of Forks B, C, and D.
- Q5 grades a ratio, which is invariant across the accepted measurement spread.
- Q6-Q7 grade derived results that converge for every student (per-trial speeds land
  341.7-344.4 m/s, so the 12-trial average is safely inside 340..346).
- Q8-Q9 are fixed conceptual multiple-choice items.
- Q1 is the evidence upload; Q10-Q11 use manual essay grader guides (style A) and require
  the student to quote their own recorded numbers.
