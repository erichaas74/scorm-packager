Unit 6 Lesson 4 - Electromagnet Design Lab

Delivery status: Buzz-native, self-contained. Fixed numeric ready for Trials 1-5; evidence based for the optimization challenge.

Source: converted from unit-ApplicationFiles/unit-6/electromagnet_lab.tsx (React + Tailwind + lucide-react).

Completed conversion work:
- Rebuilt the React/Tailwind/lucide component as one self-contained HTML file with inline CSS and vanilla JS. No CDN, icon-font, or web-font dependencies.
- Kept the simulation graphics as built: the SVG battery pack (series row and parallel stack with rails), the flexible red/green lead wires, the tapered iron/air core, the wound copper coil, the dashed blue field lines, the paperclip pile, and the lower/attach/raise test animation with its original 1000/600/1000 ms timing.
- Improved one graphic without simplifying it: the lead wires are now redrawn every animation frame so they stay attached to the moving magnet. In the .tsx they were CSS-transitioned path "d" attributes, which browsers do not interpolate, so the wires snapped instead of stretching.
- Paperclip positions now come from a seeded generator instead of Math.random, so the scene is stable across reloads and matches the evidence image.
- Removed the .tsx analysis questions (Buzz owns those now) and the simulated "Submit Final Report" alert button.
- Added the Unit 6 / Lesson 4 application shell, section nav, progress meter, and session persistence, matching the Lesson 2 electric-field lab.
- Added six trials: five fixed controlled-variable trials with a Load required setup button and setup matching, plus an open optimization challenge with a 150 paperclip goal.
- Added a required-trial evidence table, a full test log, an optional evidence PNG, ten ordered Buzz question slots, import-ready 15-point question text, setup instructions, and native Buzz grading.

Known issues fixed from the source .tsx:
- The source component called handleAnswerChange in the question textarea onChange handler, but that function was never defined, so typing in any analysis box threw a ReferenceError. The whole answer-state block is gone in the Buzz version because Buzz collects the written work.
- The source answers state declared q1-q10 but the rendered list used only 8 ids (q3 and q8 were unused, and the visible numbering ran 1-8 against non-sequential ids).

Grading design:
- Trials 1-5 lock the console conditions, so wire, current, cost, and clips lifted are identical for every student. Questions 2-6 are auto-graded numeric items with explicit tolerance ranges; a run is only recorded when the console actually matches the required setup, so a student cannot record Trial 4 with Trial 5's wiring.
- Questions 7-8 are fixed conceptual multiple choice drawn from the Trial 1/2 and Trial 4/5 comparisons.
- Question 10 is evidence based: student optimization designs vary, so it is graded on the design description plus at least three cited measured values, never on one correct configuration.
- Verified physics ceiling: the strongest legal design lifts 198 clips (60 turns, iron, 13 mm, 4 cells series, 245 cm wire, cost 36.75). 208 of the 5586 possible console combinations reach the 150 clip goal, so the challenge is reachable but requires understanding the series/resistance tradeoff.

Deliberate deviation from the conversion guide:
- Students can copy and paste normally. Numeric values remain visible in the on-screen required-trial table while students answer the native Buzz questions.
- File naming follows the unit-6 sibling convention (electromagnet_lab.html) rather than the u#l#- prefix used in units 1-4. The names are still unique across the repo, which is what the guide requires.
