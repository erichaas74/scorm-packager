Buzz Setup: Unit 1 Honors Rocket Launch Lab

What this activity is

The template stacks four independent copies of the rocket lab on one page, one per section, all flying the same fixed mission: a = 20 m/s2, t = 2.5 s, g = -10 m/s2, retro engine +20 m/s2 net igniting at one third of the apex. Every student therefore sees the same givens and the numeric keys below grade consistently.

Each section runs its own scripted flight and stops where that stage ends: Section 1 freezes at engine cutoff, Sections 2 and 3 freeze at the apex, and Section 4 flies burn, coast, free fall, and retro burn straight through to touchdown. Students press the round button to run or replay a flight as often as they like.

The simulation never prints a value the student is asked to calculate. The Kinematics Values grid shows givens and a ? in every other cell, and the altitude rail, altitude readout, velocity readout, apex/burn/retro markers, target chip, and score badge are all blanked. The mission clock runs only in Section 1, where the burn time is already a given. Section 4 runs with every numeric readout dark.

The Buzz question slots sit inside each section's Mission Brief card, directly under that section's kinematics grid and to the right of its flight view, so students read the givens and answer in the same column.

Why Section 4 asks about the whole flight. Because the burn acceleration is exactly twice gravity, the descent mirrors the ascent: the retro ignition height equals the burn height (62.5 m), the free-fall drop equals the coast height (125 m), the speed at retro ignition equals the burnout velocity (50 m/s), and the retro burn lasts exactly as long as the powered burn (2.5 s). Asking for any of those would just re-grade a Section 1–3 answer, so Section 4 grades total time, total distance, and total displacement instead — all three require every phase and none repeats an earlier value.

Step 2: Upload the template

  1. Run node unit-1/lesson-honors/build-buzz-template.js after any change to index.html, style.css, or sim.js. The build fails loudly if a source edit breaks one of its hooks.
  2. Run node unit-buzz-template-conversion-files/build-buzz-template-previews.js from the repository root.
  3. Upload u1h-rocket-launch-buzz-assessment-template.html as the assessment template.
  4. The template has ten <a:question></a:question> slots: 2 in Section 1, 2 in Section 2, 2 in Section 3, and 4 in Section 4. Question order must remain exactly as imported.

Turn OFF randomize/shuffle question order. Do not use one question per page. Buzz fills template slots in display order, so either setting drops questions into the wrong section's Mission Brief card.

Step 3: Preview as a student

  1. Confirm the page title reads Unit 1 Honors: Rocket Launch Lab Assessment.
  2. Confirm all four sections render a rocket, launch pad, minimap, and animation, and that each section's round button reads Run Burn, Run Ascent, Run Full Ascent, and Run Full Mission in order.
  3. Run each section and confirm it stops where it should: Section 1 at BURN COMPLETE, Sections 2 and 3 at APEX REACHED, Section 4 at LANDED. Then confirm the button offers a replay.
  4. Leak check. With every flight finished, confirm no section displays 62.5, 50, 125, 5.00, 187.5, 7.50, 15.0, or 375 anywhere. The only numbers on screen should be the givens: 0.0 m/s, +20.0 m/s², -10.0 m/s², and 2.50 s (plus the Section 1 timer, which counts to that same 2.50 s).
  5. Confirm Q1–Q2 land in Section 1's Mission Brief, Q3–Q4 in Section 2's, Q5–Q6 in Section 3's, and Q7–Q10 in Section 4's.
  6. Enter the nine answer-key values and confirm each numeric question grades correct.
