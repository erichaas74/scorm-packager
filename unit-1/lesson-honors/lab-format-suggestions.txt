Buzz Conversion Notes: Unit 1 Honors Rocket Launch Lab

Conversion completed
- `u1h-rocket-launch-buzz-assessment-template.html` is generated from the original lab source, with the complete existing
  graphics and animation code inlined. It stacks four independent copies of the lab, one per section.
- `sim.js` is wrapped into a `createRocketLab(root, LAB)` factory at build time. Every DOM lookup in the original goes through
  one `el` Proxy, so scoping that Proxy to a root element is all it takes to run four instances on one page. Element ids are
  namespaced per section (`s1-`, `s2-`, `s3-`, `s4-`).
- Each section runs a scripted flight and stops where its stage ends: Section 1 at engine cutoff, Sections 2 and 3 at the apex,
  Section 4 at touchdown after the full burn/coast/free-fall/retro sequence.
- The Buzz question slots live inside each section's Mission Brief card, under that section's kinematics grid.
- The native calculation-input card is removed, not merely hidden, so none of its generated inputs collide across instances.
- Every readout that would report a calculated answer is blanked: altitude rail ticks, altitude, velocity, apex/burn/retro
  marker chips, target chip, score badge, coach hints, and the recorded-flight-data card. The mission clock runs in Section 1
  only, where the burn time is already a given.
- Fixed mission: a = 20 m/s^2, t = 2.5 s, g = -10 m/s^2, retro = +20 m/s^2 net igniting at apex/3.
- 10 questions, 14 points, all auto-graded except the closing essay.

Design constraint to preserve
- Burn acceleration is exactly twice gravity, so the descent mirrors the ascent numerically: retro ignition height = burn height
  (62.5 m), free-fall drop = coast height (125 m), speed at retro ignition = burnout velocity (50 m/s), retro burn duration =
  burn time (2.5 s). Section 4 must therefore grade whole-flight quantities (total time 15.0 s, total distance 375 m, total
  displacement 0 m) rather than descent phase values, which would only re-grade Section 1-3 answers.
- Changing the burn acceleration away from 2|g| breaks the clean descent numbers (they go irrational), so keep a = 20.

Publishing workflow
1. Run `node unit-1/lesson-honors/build-buzz-template.js` after any change to index.html, style.css, or sim.js.
   The build throws if a source edit moves or removes one of the strings it hooks into.
2. Run `node unit-buzz-template-conversion-files/build-buzz-template-previews.js` from the repository root.
3. Upload the unique template file named in setup-instructions.html.
4. Turn off Buzz question randomization and do not use one-question-per-page.
